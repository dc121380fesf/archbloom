# 倒角（chamfer）实现笔记

> 2026-10-18，I 阶段第一档。这份笔记记的是「为什么这么写」和「踩过的坑」，
> 不重复代码里已有的注释。

## 为什么 chamfer 和 fillet 要分开

端口原来只有一个 `fillet: bool`。实现时发现这会把两件事混成一件事：

| | chamfer | fillet |
|---|---|---|
| 几何 | 平面切口 | 圆柱面过渡 |
| 图纸标注 | `C0.5` / `0.5×45°` | `R0.5` |
| 加工 | 铣刀斜切 | 球头刀走弧 / 成型刀 |
| 实现成本 | 内缩 + 缝合 | 曲面延伸 + 求交 + 圆弧边界 |

合并会让 agent 无法判断「我要的 R0.5 到底能不能做」。所以：
- `Capabilities.chamfer` 新增
- `Capabilities.fillet` 保持 `false`（圆弧过渡没做）
- trait 新增 `chamfer(id, edges, width, cancel)`，`fillet` 保留默认 Unsupported

**申报必须与实际一致**——这条从现在起有两个布尔位来兑现。

## 算法三步

1. **边表**（`edge_table`）：隐式边落成显式记录，每条无向边找到两个面 + 夹角
2. **面内缩**：面上每条锐边向内平移 `width`，相邻平移线求交得到顶点新位置
3. **缝合**：原面用内缩环，每条锐边补斜面，每个多锐边顶点补角面

关键点：**内缩量是「每条边」的，不是「每个面」的**。非锐边平移量取 0，
所以「只倒一部分边」不会撕裂实体——这是整套算法的立足点。

## 四个坑（按踩到的顺序）

### 1. 内缩公式漏了第二项

解交点方程 `d_prev*m1 + t*e1 = d_cur*m2 + s*e2` 时，与 `e2` 叉积消 `s`：

```
d_prev*(m1×e2) + t*(e1×e2) = d_cur*(m2×e2)
```

我一开始只写了左边第一项，右边当成 0。
**但 `m2⊥e2` 不等于 `m2×e2 = 0`** —— 实际上 `(cross(n,e2))×e2 = -n`，
投影到 `n` 上恒为 `-1`。

后果：顶点只沿一个方向内缩，底面从正方形凹成「漏斗」，体积差 10%。

### 2. 朝向判据整体反了

判断补出来的面朝里还是朝外，我用的是「多边形质心相对原棱的方向」。
可倒角面**本来就在原棱的内侧**（材料被切掉了），这个判据必然把所有面判反。

正确做法：用**相邻面外法线之和**作参考方向。凸边、凹边都成立，且是纯局部的。

### 3. 靠几何反查顶点会错配

内缩后的环丢了「原顶点号」信息，我最初用「环上离原顶点最近的点」反查。
盒子没问题；圆柱上点距 0.5mm、倒角宽度也是 0.5mm 时，最近点就是错的邻居。

改成**内缩时直接记账** `(面索引, 原顶点号) → 新顶点号`。这不是优化，是正确性。

### 4. 手推解析体积连错两次

第一次推 `V - 12·(½d²)(L−2d) - 8·(d³/6)` = 7.6053，实测 7.5627。
第二次改角块系数还是不对。

**数值积分和 FreeCAD 独立回读都指向 7.562666561**，是我错了，代码对了。

教训：复杂立体的体积解析式很容易漏项（棱端和角块会重叠），
**外部几何内核的结论优先于手推**。测试基准已改用 FreeCAD 实测值。

## 验收口径

| 项 | 盒子 | 圆柱 |
|---|---|---|
| 体积 | 7.562666667（FreeCAD 7.562666561，差 1e-7） | 减少且掉幅 < 2% |
| 面数 | 26（6+12+8） | 194 |
| 水密 | ✅ | ✅ |
| 欧拉示性数 | 2 | 2 |
| STEP | 导出 + 自检通过 | — |

失败路径也验收了：
- 宽度为 0 → 报错
- 宽度大于面尺寸（环翻转）→ 报错（判据：内缩后面积反而变大）
- 边号越界 → 报错

## 已知边界

1. **布尔件倒角会失败**。开孔板 3148 个面，孔壁碎片 1e-6 量级，比 0.3mm 倒角还小。
   报错带诊断，但**当前无法只倒外框**——缺「查边」接口。
2. **凹边未验证**。算法按凸边推导，凹边（内角）的内缩可能自交。
3. **圆角（fillet）未做**。真圆角要圆柱面 + 圆弧边界 + 曲面求交，是下一档工作。
4. **`tessellate(tol)` 仍不重细分**（继承 D 阶段的限制）。
