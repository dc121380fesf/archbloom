# 第一部分：同一个问题两次修不好，就停下来

## 规则

**同一个问题连续两次修复失败 → 禁止直接试第三次。**

必须先做两件事：

1. **整体观察**——跳出当前那一行代码，看问题赖以成立的前提
2. **查权威**——让 researcher 上网查成熟内核（OCCT / SMLib / ACIS / CGAL）和论文怎么做的

## 为什么定这条

### 圆角的代价：试了五次才转向

| 第几次 | 做法 | 结果 |
|---|---|---|
| 1 | `corner_idx` 改多值 | 盒子坏（边界 0 → 202）|
| 2 | 3a 环路展开 | 盒子坏 |
| 3 | 脚本按括号切函数 | 误删 4 个函数 |
| 4 | 降锐边阈值 30° → 20° | 圆柱更糟（544 → 896）|
| 5 | 多值 + 3b 一致 + 坐标去重 | 盒子仍坏 |
| **6** | **找求知** | **一次拿到正确数学** |

**前五次合计约 8 小时，全是同一处的试错。** 求知给出的答案只有一行：

```
切点 p = c + R·n_f，它同时满足 |p−c| = R 和 (p−c)·e = 0
⇒ 切点本来就是大圆上的点，两个点严格重合
```

**我从头到尾在改"怎么让两个点对上"，而正确答案是"这两个点本来就是一个"。**

### 连续布尔的对照：第二次就转向

| 第几次 | 做法 | 结果 |
|---|---|---|
| 1 | 发现 `solid_to_polygons` 丢洞 | 定位到根因 |
| 2 | 带洞面三角化 | 边不共享，panic |
| **3** | **找求知** | **拿到 Fix A + 验收矩阵** |

**两次就转向，代价约 2 小时。** 求知给的东西直接可落地（数据结构定义、改动行数、验收公式）。

## 「整体观察」具体做什么

不是"再想一遍"，是四个动作：

**① 列出前提假设**

把"我一直在依赖什么"写下来。圆角的例子：

- 假设 1：球面片与柱面片的交线是大圆 ← 对的
- 假设 2：圆角面的端点要从"沿棱推到球面"得到 ← **错的**
- 假设 3：B-rep 要求顶点唯一，所以两点必须合并 ← 对的，但**前提 2 错了，这个矛盾根本不存在**

**② 用量化数据验证每个假设**

不是"我觉得这里可能不对"，是"哪个数字对不上"：

```
盒子端点间隙 0.2828 = 1.4142·R     ← 恰好 √2R
圆柱 16 段    1.9616·R
圆柱 128 段   1.9994·R             ← 不随 N 缩小
```

**"不随 N 缩小"这个反常**，才是真正的线索。如果它随 N 缩小，那就是离散误差；不缩，说明是**几何定义**问题。

**③ 问「我一直在看的地方之外」**

圆角我一直在看「角部两个点怎么接」，从没问过「这两个点为什么不是同一个点」。

**④ 把反常写成一个能被证伪的预测**

交给 researcher 时，最好附上自己的预测，这样她要么验证要么推翻。求知这次给了一个（间隙随 N 缩 3.97 倍），我实测推翻——但**推翻本身就是进展**，它把可能性压缩了。

## 「查权威」具体怎么问

**给具体问题，不要"帮我查圆角"。** 这次有效的问法是：

- "OCCT 在球面片与柱面片交界处，共享的是同一个 `TopoDS_Vertex` 吗？那个顶点落在大圆上还是切点上？"
- "圆柱顶边（闭环棱）在 SMLib 里归哪一类？有没有公开的分类表？"
- "如果布尔结果必然产生带洞面，成熟内核怎么做到任意多次布尔？"

**附上自己的测量数据。** 数据能让对方验证或证伪，也能让她的结论直接对上你的场景。

**要求她指出「业界也没有」。** 这次求知在连续布尔上直接说「无洞中间态 + 无限次布尔，没有干净解法」——**这句话本身比任何方案都值钱**，它告诉我别再走那条路。

# 第二部分：问题一 —— 圆角

## 根因

`trim_to_sphere` 做的是「沿棱方向推到球面」，得到的是**棱上的点**，不是**切点**。两条棱沿不同方向内缩，端点间距：

```
gap = 2R·sin(θ/2)        θ = 两条棱在顶点处的方向夹角
```

实测五点全中：

| 案例 | θ | 2R·sin(θ/2) | 实测 |
|---|---|---|---|
| 盒子 | 90° | 1.4142R | 1.4142R ✓ |
| 圆柱 N=16 | 157.5° | 1.96157R | 1.9616R ✓ |
| 圆柱 N=64 | 174.375° | 1.99759R | 1.9976R ✓ |
| 圆柱 N=128 | 177.1875° | 1.99940R | 1.9994R ✓ |

N→∞ 时两棱趋于反向，弦→直径 2R。**"不随 N 缩小"是这个机制的必然，不是异常。**

## 解法第一步：端点统一写切点（小时级）

```rust
// 现在
fn trim_to_sphere(p0, dir, sphere, r) -> Option<Point3>
  // 沿 dir 推 → 棱上的球面点

// 改成
fn corner_point(center: Point3, face_normal: Vector3, r: f64) -> Point3
  // center + r * face_normal
```

**数学保证**（两行恒等式）：

```
|p − c| = |R·n_f| = R                     → 在球面上
(p − c)·e = R·(n_f·e) = 0                 → 在柱面上（n_f ⊥ e）
```

**验收断言**：同一面上两条棱给出的端点，间距 **bit 级为 0**。

**连带影响已核查**：`arcs` 的基底 `u0 = normalize(f1_start − ca 的垂直分量)`，
改成切点后 `p − ca = R·d̂ + R·n_f`，垂直分量仍是 `R·n_f` → **`u0` 方向不变**。

## 解法第二步：圆柱顶圆走闭环分支（1-2 人日）

SMLib 把这类单列为一类 `SmFilletNx1ClosedCorner`，官方原文：

> 闭环棱（**i.e. top edge of a cylinder**）that attaches to the vertex two times.
> **If the edge meets itself tangentially (as with a cylinder), the fillet surface
> will be closed and joined without any trimming.**

**结论：圆柱顶圆不需要角部，就是一张自闭的圆环面。**

参数（求知给全了）：

```
spine    = 圆(Rc + R, z = H + R)          ← 滚球球心轨迹
band     = Torus(主半径 Rc + R, 管半径 R, 中心在轴上 z = H + R)
下边界   = 圆(Rc + R, z = H)              ← 切顶面，用于裁剪顶面
上边界   = 圆(Rc,     z = H + R)          ← 切侧面，用于裁剪侧面
拓扑     = 1 张 Torus 面 + 2 条闭环边 + 至多 1 个 seam 顶点
角部     = 无
```

**我们 5 类曲面里正好有 `Surface::Torus`，边里正好有圆弧**——不需要改数据结构。

**验收**：圆柱顶边圆角后水密、欧拉 2、体积对 FreeCAD 在 0.1% 内。

## 分类参考（SMLib 公开表）

| 类型 | 触发条件 | 做法 |
|---|---|---|
| `Nx1 Closed` | **闭环棱**（圆柱顶圆）| 切向 ⇒ 圆角面自闭、零裁剪、零角部 |
| `3x1` | 3 棱只倒 1 条 | 圆角延伸到相邻面相交 |
| `3x2` | 3 棱倒 2 条 | 两圆角面**求交裁剪**，不加角补片 |
| `NxN` 同凸性 | 所有棱都倒 | 3/4/N 边切向补片，**恒半径简单情形是球面** |
| `NxN` 混凸性 | 轨线不全相交 | 先在面上补 blend curve，解析面有时是圆环 |

**盒子角（3 棱全倒）= `NxN`，球面三角，我们已实现。**

# 第三部分：问题二 —— 连续布尔

## 根因

**布尔代数的封闭性要求中间态支持带洞面。** 挖一个盲孔，顶面立刻有洞；挖一个腔，实体立刻多一个内壳。

**「无洞中间态 + 无限次布尔」在数学上不成立**——求知查遍 OCCT / ACIS / CGAL / brepkit，明确说没有干净解法。

我们的 `Polygon`：

```rust
pub struct Polygon {
    verts: Vec<Point3>,
    plane: Plane,
    surface: Option<Surface>,
    // 没有 holes
}
```

第一次布尔产生的带洞面（外环 132 点 + 孔环 64 点），第二次布尔时洞被 `solid_to_polygons` 丢弃。

## 实测症状

| 布尔次数 | 水密 | 欧拉 | 体积误差 |
|---|---|---|---|
| 0（光板）| true | 2 | **0** |
| 1 个孔 | true | 0 | 0.046% |
| 2 个孔 | **false** | **−18** | 0.095% |
| 3 个孔 | false | −62 | 0.100% |
| 4 个孔 | false | −118 | 5.03% |
| 1 孔 + 方槽 | true | 0 | **34%**（比光板还大）|

## 解法（Fix A，400–700 行，4–6 人日）

| 步 | 改什么 | 行数 |
|---|---|---|
| 1 | `Polygon` 加 `holes: Vec<Vec<Point3>>`；定向约定：依 `plane.normal`，外环逆时针、洞顺时针 | ~60 |
| 2 | `solid_to_polygons` 读 `f.holes`；面积 = 外环 − Σ洞；断言洞在外环内、面积 > 0 | ~40 |
| 3 | 切分：带洞平面裁剪（可用 `geo` crate 的 `BooleanOps`，官方文档写明「正确处理洞」）| ~80–200 |
| 4 | 分类：even-odd 射线法，或 `PIP(outer) && !PIP(any hole)` | ~30 |
| 5 | 重建：**顶点用 ID 而不是坐标**重建索引；每条边登记一次、恰 2 个使用 | ~100–200 |

**第 5 步是关键。** 上次三角化失败就是因为「三角形的边是面内私有的，邻面还持整段原边」——一条边 3+ 个使用或 1 个使用，非流形。7217 顶点 / 7257 面、欧拉 −14 就是这个症状。

## 验收矩阵（闭式基准，可直接断言）

| 案例 | 期望欧拉 | 期望体积 |
|---|---|---|
| 平板 + k 个通孔 | **2 − 2k**（k=1 → 0 ✓ 已对）| V₀ − k·πr²t |
| 平板 + k 个盲孔 | **2**（不增亏格）| V₀ − k·深度体积 |
| 封闭内腔（铸件空腔）| **4**（两壳，各 χ=2）| V_outer − V_cavity |
| 链式 4–6 次布尔 | 随最终亏格 | 逐步闭式递推 |

**现在 2孔=−18、3孔=−62、4孔=−118，与期望 −2/−4/−6 的差值就是非流形边的直接度量。**

## 不做的事

- **不推荐**「桥缝拆无洞 + 事后同域合并」：3–8 人日、长期维护贵（人工边污染圆角/选择/导出）
- **绝对不要**「每次布尔后重三角化」：那就是 7217/7257 那条路的放大版
- **不要**用 sewing / 多值顶点去掩盖偏差源

# 第四部分：优先级

```
① 圆角第一刀（c + R·n_f）              小时级，立刻见效
② 连续布尔 5 步                        4-6 人日，最高价值
③ 圆角闭环环带                         1-2 人日
```

**连续布尔优先级高于圆角**——它决定内核能不能做真实零件（安装板、支座、法兰全要多次布尔）；
圆角只是「有功能缺一块」。

# 附：这次的教训清单

1. **验收样本不能只挑能过的。** 之前一直用「单孔开孔板」当验收，精度看起来很好；
   换成真实零件（4 孔 + 槽）才暴露连续布尔全线崩溃。**以后每个能力都要拿真实零件验。**
2. **改核心数据结构前先打 tag。** 圆角那五次失败全靠 `git checkout` 救回来。
3. **脚本改源码要验。** 按括号深度切函数那次误删了 4 个函数，因为判断条件写错。
4. **「发现了什么」不重要，交付了什么才重要。** 第五次失败后我写了长篇「发现矛盾」，
   但功能仍然不能用——那是包装。
