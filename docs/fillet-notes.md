# 圆角（fillet）实现笔记

> 2026-10-18。**几何公式已验证正确，角部拼接多次尝试仍未完成。**
> 已查过 NVIDIA SMLib 的权威方案（见末节），方向明确，但实现细节还没跑通。

## 与倒角的区别

| | chamfer（已可用） | fillet（本笔记） |
|---|---|---|
| 连接面 | 一个平面 | 一段圆弧 |
| 图纸 | `C0.5` | `R0.5` |
| 加工 | 铣刀斜切 | 球头刀走弧 |

## 已验证正确的几何

对凸边，两侧面法线 `n1`、`n2`，内法线 `m1 = -n1`、`m2 = -n2`：

```text
bis = normalize(m1 + m2)              角平分线
θ   = π - acos(n1·n2)                 内部二面角
c   = 边点 + bis * (R / sin(θ/2))     圆心
p1  = c - R*m1                        切点（落在 f1）
p2  = c - R*m2                        切点（落在 f2）
```

90° 凸边 R=0.2 时：`c=(0.2, 0.2)`，切点 `(0.2,0)` 和 `(0,0.2)`。

**实测**（盒子 2m 边长，**单边** R=0.2）：

| 段数 | 体积 | 理论 7.982832 |
|---|---|---|
| 1 | 7.984379 | |
| 8 | 7.988286 | |
| 32 | 7.988538 | |

误差 0.07%，方向正确。

## 四轮角部尝试全部失败

| 方法 | 结果 | 失败原因 |
|---|---|---|
| ① 单独算切点 | 单边对，全边体积差 24.7%、水密 false | 顶点周围 6 个切点，补面接不拢 |
| ② 平面多边形补角 | 孤边 132 条 | 边没分段，切点直接连成横跨整面的长边 |
| ③ 复用倒角骨架 | 体积 4.76 vs 7.80（差 39%） | **内缩点 ≠ 切点** |
| ④ 球面三角 | 体积 5.87 vs 7.80（差 24.7%） | 切点组织方式仍是老问题 |

**方法③ 的教训最值得记**：

```text
倒角的内缩点：(0.2, 0.2, 0)   ← 面内两个方向都缩
圆角的切点：  (0.2, 0,   0)   ← 只朝一个方向缩，弧与面相切
```

我一开始以为「圆角 = 倒角 + 弧形」，实测发现边界终止点根本不同，
弧的半径从 0.2 变成 0.346。

只是全边角部还有一段没接上。

## 方法⑤ 已实现的部分（代码里保留）

**球心精确求解**（Cramer 法则解 3x3）：

```text
对每个相邻面 i：(c - v) · m_i = R      m_i = -n_i
```

盒子角 (0,0,0)、R=0.2 解出 `c = (0.2,0.2,0.2)`——已验算，正确。

**轨线方向**：`边点 → 圆心的向量投影到面内`。

这条不能写成 `cross(n, edir)`——叉积的符号依赖环方向，盒子两个面一个对一个反，
实测体积超过原体积（8.01 / 8.65），说明弧朝外凸了。

**轨线端点**：轨线与球面求二次方程取近根。

**单边实测**：7.988286 vs 理论 7.986265，差 **0.03%**。

## 还差什么

全边时角部的球面片没接对（5.39 vs 7.80）。球心是对的，
问题在「轨线端点 → 球面三角的顶点」这一步：现在是把轨线端点直接当三角顶点，
但它们应该落在球面上，而轨线与球面的交点才是真正的边界点。

下一步：
1. 核对 `trim_to_sphere` 的解（二次方程取哪个根、方向对不对）
2. 球面三角的顶点必须是**轨线与球面的交点**，不是轨线起点
3. 角部面要细分成球面片（现在是一个平三角，会偏大）

## 踩过的坑

**弧的转向差 180°**。圆弧要从「圆心指向切点」的方向插值（`-m1 → -m2`），
不是 `m1 → m2`。写反会把弧甩到实体外面——实测 90° 边转到 z=0.38、体积差 5 倍。

## NVIDIA SMLib 的权威方案（已查证）

来源：<https://docs.nvidia.com/smlib/manual/smlib/fillets>

他们把角部按 `NxM` 分类（N 条边交汇、M 条要圆角）。**盒子角是 `NxN Same-Convexity`**：

> "This case will create a **3, 4 or N-sided tangential corner blend** between all of
> the adjacent fillet surfaces. In some cases the corner will be an
> **analytical surface (Sphere)**. In the N-sided corner case, when N > 3,
> multiple four-sided patches will be created to fill the corner."

**角部是球面片**。盒子角 (0,0,0)、R=0.2：三个切点 `(0.2,0.2,0)`、`(0.2,0,0.2)`、
`(0,0.2,0.2)`，**球心 `(0.2,0.2,0.2)`**——到三个切点距离都是 R。

### 其他关键概念（原文摘录）

- **Rail Curves（轨线）**：圆角面与两个原始面的交线，"先算轨线，再算圆角面，
  最后处理角部"
- **3x2 Corner**：三条边交于一点、两条要圆角
  - 相切：直接连接，不裁剪
  - 同凸性：「fillet surfaces will be intersected and a **bevel** created」
  - 混合凸性：「a **corner patch** will be created」
- **NxN Mixed-Convexity**：轨线不相交时，「a blend curve will be made between
  the rail curves on the given face... corner will be an analytical surface (Torus)」
- **大半径情形**：轨线自交、翻到相邻面（Cliff Rollover / Tangent Rollover）、
  与孔洞相交等，SMLib 都有一整套 handler

## 下一步（要按 SMLib 的流程重构）

1. **先算轨线**：每条圆角边的两条轨线，端点由球面求交决定
2. **角部按 NxM 分类**：先只支持 NxN Same-Convexity（盒子场景）
3. **球面片**：球心由「到三面距离=R」精确求解（不是我现在用的近似公式）
4. **轨线端点在球面上**：这才是切点的正确定义——不是「面上距边 R 的点」，
   而是「轨线与球面的交点」
5. 然后升级真圆柱面

**关键认知**：我一直在用「每面一个切点」的组织方式，而 SMLib 是「**轨线**」——
一条边有两条轨线，轨线一直延伸到角部与球面相交。这是结构上的差别，
不是参数调调就能对上的。
