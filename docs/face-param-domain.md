# 面的参数域化（A 方案设计稿）

> 状态：设计稿，未实施
> 目标读者：三个月后回来接手的人（很可能是我们自己）

## 一句话

把 `Face` 从「多边形环 + 曲面标签」改成「曲面 + 参数域边界」，
让**离散顶点成为派生结果，而不是真相**。

---

## 1. 为什么

### 现状

```rust
pub struct Face {
    pub surface: Surface,       // 只是标签：STEP 导出时被读，计算时不看
    pub verts: Vec<u32>,        // 真正的几何：所有计算都走这里
    pub holes: Vec<Vec<u32>>,
}
```

**`surface` 和 `verts` 互不约束。** 一个 16 边形的环可以挂 `Cylinder` 标签，
于是一个实体同时有两个身份：

| 用途 | 走哪条路 | 结果 |
|---|---|---|
| 体积、布尔、倒角、圆角 | `verts` | 16 棱柱 |
| STEP 导出 | `surface` | 圆柱 |
| 三角化 | 两条都不全看，按 `Surface` 类型 if-else | 部分正确 |

### 由此长出来的补丁

| 补丁 | 行数 | 它补偿的是什么 |
|---|---|---|
| `fix_holes.rs` | 299 | 合并产生的洞边界是 955 点锯齿，导出时用孔壁端圆替换 |
| `simplify_collinear` | 40 | 合并留下 132 点共线外环 |
| `split_rings` | 60 | 合并产生 2894 点蛇形环 |
| `tessellate(tol)` | — | **接收 tol 参数然后完全忽略** |
| `triangulate` 里的球面中点细分 | 60 | 只有球面有细分，柱面/锥面/环面裸扇形 |
| 圆角的「2 棱角部」 | — | 圆柱是 16 边形，每个转折点都是 2 棱角部 |

**六个补丁，一个病根。**

### 一个具体证据

`cylinder_solid` 的注释原文：

> 圆柱侧面离散成 N 个四边形面，它们**共享同一个 `Cylinder` 标注**

「共享标注」这四个字就是妥协的签名——真实几何里那是**一个面**，
不是 N 个面共享一个标签。

---

## 2. 目标结构

```rust
pub struct Face {
    /// 曲面。所有几何查询（法线、求值、细分）都从这里出发。
    pub surface: Surface,

    /// 参数域边界：外环 + 洞。
    /// 点在 `surface` 的 (u,v) 参数空间里，闭环、首尾不重复。
    pub boundary: Vec<Vec<[f64; 2]>>,

    /// 这个面承诺的弦高误差（米）。
    /// 细分点数由此反解，不再是硬编码的 16 / 64 / 8。
    pub tolerance: f64,

    /// 离散后的顶点索引（指向 `Solid.verts`）。
    ///
    /// **派生缓存，不是真相。** 由 `(surface, boundary, tolerance)` 决定，
    /// 拓扑（边、半边、欧拉数、体积）全部走它。
    /// 缓存失效时用 `resample()` 重建。
    pub verts: Vec<u32>,
    pub holes: Vec<Vec<u32>>,
}
```

### 不变量（`Face::check()` 要验的）

1. `verts` 中任一点到 `surface` 的距离 ≤ `tolerance`
2. `verts` 的点数 ≥ 边界所需的段数
3. `boundary` 每个环闭合、不自交
4. `holes` 与 `boundary[1..]` 一一对应（编号一致）

**第 1 条是关键**：它让「标签和几何不一致」在检查层面不可能蒙混过关。

## 3. 四个设计决策

### 决策一：`verts` 保留，不移除

**理由**：拓扑（半边、边表、欧拉数、体积）全依赖顶点索引。移除它等于重写
`solid.rs` / `edges.rs` / `merge_he.rs` / `csg.rs` 全部。

**代价**：`verts` 和 `boundary` 有两个真相源，靠 `check()` 保证一致。

**为什么不干脆"只保留 boundary"**：那样每次查拓扑都要现算细分，一个布尔操作
要算几十万次——性能无法接受，而且边号会随细分策略变化而抖动。

### 决策二：曲面自己会说「怎么细分」

```rust
impl Surface {
    /// 在参数域内按 tolerance 生成折线。
    /// Plane 直接返回矩形四角；Cylinder 按弧长反解段数；Sphere 按经纬。
    pub fn tessellate_boundary(&self, boundary: &[Vec<[f64;2]>], tol: f64)
        -> Vec<Vec<[f64;3]>>;

    /// 参数 → 空间
    pub fn eval(&self, uv: [f64; 2]) -> [f64; 3];

    /// 空间 → 参数（牛顿迭代，给 booleans 用）
    pub fn project(&self, p: [f64;3]) -> Option<[f64;2]>;
}
```

细分规则由曲面类型决定，不是调用方 if-else。

### 决策三：布尔不动 `Face`，只在 Polygon 层跑

**理由**：布尔是「切面 → 分类 → 缝合」，全程在平面多边形上。它输出的是
**平面碎片**，这些碎片的 `boundary` 就是它们的环（平凡情况）。

**所以**：`Polygon` 保持不变，`rebuild` 产出 `Face` 时：
- 平面碎片 → `boundary = 环的 (u,v)`（在平面参数系里）
- **曲面面**（圆柱侧面）→ 布尔前先离散成平面碎片，布尔后**不还原**

**这意味着**：布尔之后圆柱就变成多面体了。这是**现状**，不是退步——
真正的曲面布尔（相贯线）是另一个项目（`curved_bool = false` 就是在说这件事）。

### 决策四：`tolerance` 存在 `Face` 上，不存全局

**理由**：不同面的精度需求不同（大平面 1mm 够，Φ5 孔要 0.05mm）。
全局一个 tol 会逼着所有面用最细的那个。

**但**：`Solid` 可以带一个默认 tol，构造时填进去。

## 4. 迁移六步

**每步都必须能独立回退。每步结束都要跑 253 测试 + 圆角 0.0491% 对账。**

### 步 0：加字段，不启用（零行为变化）

- `Face` 加 `boundary: Option<Vec<Vec<[f64;2]>>>`、`tolerance: Option<f64>`
- 所有构造器填 `None`
- `check()` 对 `None` 直接返回 `Ok`

**验收**：253 测试全绿，圆角 0.0491%，合并 70 面。

**回退**：删字段。

### 步 1：`check()` + 全实体体检

- 实现 `Face::check(tol) -> Result<(), String>`
- 遍历所有测试里的实体，统计「有多少面本来就不自洽」

**产出**：一张清单——哪些面声称是曲面、实际离散对不上、误差多少。

**这一步不修任何东西，只让债显形。** 它的价值是**量化后续工作量**。

**回退**：不需要（纯新增检查）。

### 步 2：圆柱构造器填 `boundary`

- `cylinder_solid` 侧面仍产出 N 个面，但每个填自己的小矩形 `boundary`
- `tolerance` 按 `2πR/N` 反解

**验收**：`check()` 通过；253 测试全绿（不该有任何变化）。

**回退**：填回 `None`。

### 步 3：`Surface::tessellate_boundary` + `eval`

- 实现三个曲面（Plane / Cylinder / Sphere）的 `eval`
- 实现 `tessellate_boundary`（按 tol 反解段数）
- **只使用，不替换**

**验收**：新函数生成的顶点与现有 `verts` 距离 ≤ tol（在测试里断言）。

**回退**：删函数。

### 步 4：圆柱侧面合并成 1 个面

⚠️ **这是第一个真正的行为变化**

- `cylinder_solid` 侧面 = 1 个 `Face`，`boundary = [[0,0],[2π,0],[2π,H],[0,H]]`
- `verts` 由 `tessellate_boundary` 生成

**验收**：
- 面数 18 → 3
- 边数 48 → 2（顶圆、底圆，各一条闭环）
- 体积对真圆柱误差 < 0.5%（16 段 → 按 tol 反解，可能更细）
- 253 测试**会挂一批**（面数/边数断言），逐个改成新数字

**风险**：这是最危险的一步。`k3` / `k5` / `k7` 的数字都会变。

**回退**：`git revert` 这一个提交。

### 步 5：退休补丁

- 删 `fix_holes.rs`（洞边界由圆柱的 `boundary` 天然是圆）
- 删 `simplify_collinear`（参数域边界只有 4 个角）
- 删 `split_rings`（面由参数域定义，环天然简单）
- `tessellate(tol)` 真正传给 `tessellate_boundary`

**验收**：每删一个，FreeCAD 对账体积不变。

**这一步收益最大，风险最低**——因为前面四步已经把地基换好了。

---

## 5. 风险

### 风险一：布尔路径会被牵动

`csg.rs` 的 `Polygon` 有 `surface` 字段，`rebuild` 会把它写回 `Face`。
如果 `Face` 多了必填的 `boundary`，`rebuild` 就得为每个碎片造一个。

**对策**：平面碎片的 `boundary` 就是环的 (u,v)，**平凡但有工作量**。
`rebuild.rs` 会从 181 行涨到 ~250 行。

### 风险二：边号不稳定

现在边号 = 顶点对排序后的序号。`verts` 变化（细分策略变）→ 边号全变。

**这不是新问题**（`edges.rs` 的文档里已经写了「任何一次几何运算之后边号都可能重排」），
但 A 会**加剧**它。

**对策**：不改边号机制；在文档里强调「查边 → 操作」之间不要插入别的运算。

### 风险三：内存

每个 `Face` 多存一份 `boundary`（4-200 个 `[f64;2]`）。开孔板 73 面 × 平均 20 点
× 16 字节 = 23KB。可忽略。

### 风险四：我可能又改坏东西

**这是最真实的风险。** 本项目里我已经三次因为「想一次改一大片」破坏已验证路径
（`corner_idx` 结构、3a 环路展开、脚本切函数）。

**对策**：
- 每一步一个提交，提交前必须 253 测试全绿
- 不用脚本批量改源码
- 步 4 之前先把当前状态打 tag，出事直接回滚

---

## 6. 收益（可量化）

| 项 | 现在 | 之后 |
|---|---|---|
| 退休的补丁 | — | 3 个模块/函数（`fix_holes`、`simplify_collinear`、`split_rings`）|
| `tessellate(tol)` | 假接口 | 真生效 |
| 圆柱面数 | 18（16 片共享标签）| **3** |
| 圆角的 2 棱角部 | 存在 | **消失**（闭环棱无端点）|
| 精度控制 | 硬编码 16/64/8 | 由 `tolerance` 反解 |
| 「标签 ≠ 几何」 | 可能 | **`check()` 拦住** |

**最值钱的是最后两行**：前五项是便利，最后两项是**正确性**。

---

## 7. 明确不做

- **曲面布尔（相贯线）**：`curved_bool` 保持 `false`。A 不碰这个。
- **NURBS / 放样 / 扫掠**：范围早就写死了。
- **多壳实体**：`Solid` 仍是单壳假设。
- **改边号机制**：另开一轮。

---

## 8. 如果只能做一半

**做步 0、1、2**（加字段 + 体检 + 圆柱填 boundary）。

- 零行为变化
- 拿到「有多少面本来就不自洽」的量化清单
- 不需要动布尔、不动圆角

**这三步的价值**：把「A 到底有多大工作量」从猜测变成数字。
如果体检发现 90% 的面都不自洽，那 A 就是必须的；如果只有 3% 不自洽，
说明问题被高估了，可以只修那 3%。

**在没拿到这个数字之前，步 4 不该动手。**
