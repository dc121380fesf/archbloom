# 面片合并：洞的边界判定（未完成）

> 2026-10-18。面数与洞的数量已经对了，**洞的形状还不对**。
> 这份文档记录诊断结果、试过的方案、以及下一步该往哪走。

## 已修的两个 bug

**① 多重复顶点只切了第一个**

两个面共享 3 条边时，拼接后的 ring 会出现 **2 个**重复顶点
（实测 `[(14,2,17),(5,1,18)]`），原实现只按第一个切，第二个被忽略。
改成用栈判环：沿 ring 走，遇到已出现顶点就闭合一个环并回退。

**② 合并后孤立顶点没清理**

面合并后大批顶点不再被任何面引用（V 不降、E 和 F 降），欧拉数飙到 2613。
改成重建顶点池，只保留被引用的。

## 未解决：洞的边界是自交的

```
外环 132 点 | 全部在板边上   ✓
洞   85 点 | 在孔圆上只有 44 ✗
洞 y 范围 0.0004~0.0150（应 0.005~0.015）
```

洞被"拉"到了板边附近——**残留的径向切分线**。64 个扇区的径向边本该在合并时
互相抵消，没抵消掉的留在了洞的边界里。

### 根因：贪心拼接不保证环是简单的

每次拼接两个面、遇到重复顶点切环——这个过程没有全局的平面图遍历，
环的边界取决于拼接顺序。面数、体积、水密都能对，但洞的边界可能是自交路径。

## 试过但失败的方案：平面图面提取

思路：把整个壳的边当成平面图，从每条半边出发按最右转走回起点，直接提取标准面。
理论上每个面天然是简单环，与顺序无关。

**实测失败**：

```
输入：面 3148 顶点 3088 边 12472
输出：1429 个面，欧拉 -1747，最小面 3 点（全是三角形）
```

原因：**平面图面提取只对真正的二维平面图成立**。三维壳体的每个顶点周围，
边不在同一个平面里——最右转没有"平面"可依。

要成立得按每个曲面分别做平面图（曲面展开到 2D 再提取），但边同时属于两个曲面，
这个划分本身就难界定。代码已删除，不留半成品。

## 下一步可能的方向

1. **按曲面分组做平面图**：同一 `Surface` 的面片，把它们的边投影到该曲面的参数平面，
   在 2D 上做面提取。难点是跨曲面的边怎么处理。
2. **拼接后做环的几何修复**：检测洞边界上的"非圆"点（不在任何解析曲面上），
   尝试把它们收敛掉。启发式，不保证正确。
3. **接受现状**：面数 73、体积精确、水密——STEP 走全平面。对加工端来说，
   拿到的是"正确但多面体化"的文件，不是坏文件。
