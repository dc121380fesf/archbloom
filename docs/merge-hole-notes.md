# 面片合并：洞的边界判定（未完成）

> 2026-10-18 凌晨。面数与洞的数量已经对了，**洞的形状还不对**。
> 这份文档记录诊断结果和下一步该改哪里，避免下次从零查起。

## 当前成果（可交付）

开孔板 20×20×5mm，中心 Φ10 通孔：

| 指标 | 0.4.1 | 现在 |
|---|---|---|
| 面数（3148 起） | 169 | **133**（-95.8%） |
| 带洞面 | 47 个碎片 | **2 个**（顶/底各一） |
| 体积 | 精确 | **精确**（一字不差） |
| 欧拉 | 0 | 0（带一通孔 = 2−2g，正确） |
| 水密 | ✓ | ✓ |

这一步的实现只有一行判断——形成洞时检查面积占比：

```rust
if small / big < 0.02 { return None; }
```

小环面积不到大环 2% 的，不是真孔，是「提前闭合」留下的缝隙。
真实 Φ10 孔在 20×20 板上占比约 20%。

## 未完成：洞的形状是错的

诊断一个带洞面：

```
洞 955 点，其中在圆上(r≈5mm) 只有 17 个，偏离 938 个
偏离点的半径 7.8 ~ 9.0mm（远在孔外）
角度间隔中位数 5.625°（正好 64 段的步长），但最大 247.5°
```

**洞的边界把外环的点划进来了。** 数量上凑巧是「2 个洞口」，形状完全错位。

### 根因

拼接后 ring 出现重复顶点 v（出现在位置 p1、p2），我按**索引位置**切成两段：

```rust
let ring_a = ring[p1..p2];
let ring_b = ring[p2..] + ring[..p1];
```

但这两段不是「外环 + 洞」——它们是**两条路径**，各自的几何范围取决于拼接顺序，
和真实的边界划分没有对应关系。

### 为什么 STEP 那边没炸

`to_step_impl` 有护栏：所有带洞面的洞必须是圆，否则整份退回全平面。
所以现在开孔板走的是全平面路径——**安全，但不是想要的结果**。

## 下一步：重新设计环分割

不能再按索引切。要按几何切：

1. 拼接后 ring 有重复顶点 v（p1、p2 两处）
2. **从 v 出发沿两条路径走，直到再次相遇** —— 得到两个闭合环
3. 判断哪个在外：面积大的是外环，小的在内部且不相交 → 洞
4. 两个环都必须是**简单环**（不自交），否则这次拼接整体失败

关键区别：第 2 步是「从 v 出发沿路径走到再次相遇」，不是「按位置切数组」。
位置切法在遇到多段重复顶点时会串错。

### 验收口径

- 带洞面的洞，顶点数 = 圆柱段数（64）
- 洞的每个顶点到圆心距离一致（相对差 < 1e-6）
- 圆柱面的 `CYLINDRICAL_SURFACE` 能写出来，FreeCAD 回读 `isClosed() == True`
- 体积与合并前一致

### 风险

这是合并算法的核心。改坏了会连累已经正确的 133 面成果，
必须先把当前状态打成测试基线（面数 133、体积精确），改完逐条比对。

## 另一个已知限制

即使洞的形状修好了，**只合并平面**这条还在：圆柱侧面碎片不参与合并
（边消除会把顶圈底圈误判成外环+洞）。所以孔壁在 Solid 里仍是 64 个面，
靠 STEP 写出时按 `Surface::Cylinder` 分组才合成一个曲面。
